# Внешние интеграции

---

- Внешняя система (платёжка, фискализация, камеры, СКУД, партнёр) — **адаптер в Infrastructure, названный по внешней системе**, а не по нашему домену: `infrastructure/http/{provider}/{product}` (Go) / `Infrastructure/Http/{Provider}/{Product}` (PHP). Реализует интерфейсы доменов-потребителей; один адаптер может обслуживать несколько доменов. Свои БД/кэш — по `{domain}/{module}`. Полная таблица — `stacks/go/go-sdk/infra.md`, «Раскладка по типу». Домен и сервис не знают про HTTP.
- Клиент (HTTP, SDK партнёра) не создаётся внутри репозитория — инжектируется через DI.
- Исходящие HTTP — только через инструмент стека (`gosdk-http-request-builder`; в PHP — клиент из `mps/utils` или интеграционный пакет `mps/*-service-integration`). Голый `http.Get` / `Http::get` — нет.
- На уровне системы: **одна интеграция — один сервис/модуль**. Несколько несвязанных внешних систем за одним «integration-service» не собираются; бизнес-сервис не ходит во внешнюю систему напрямую.
- Входящие вебхуки — отдельный контекст точки входа (`integration`, `lpm`), проверка подписи — middleware (как `VerifyLpmSignatureMiddleware`).
- Таймауты, ретраи, идемпотентность — `approaches/patterns/`.
- Секреты интеграций — только из конфига/env; в БД — зашифрованными (как `FiscalCredentialEncrypter`).
- Новая внешняя система или протокол — согласование до кода (`regulations/technical-approval.md`).
