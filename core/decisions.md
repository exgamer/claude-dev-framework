# Журнал решений

Почему правила такие, какие есть. Перед тем как спорить с правилом — посмотреть сюда.
Открытые споры = обязательное обсуждение с пользователем, если задача их задевает (см. `core/principles.md`). Пока спор открыт, в новом коде — как в эталоне фреймворка (`stacks/<stack>/examples/`; он написан по основным эталонам: Go — `parking-session-service`, PHP — `parking_app`), и это явно проговаривается пользователю.

Префиксы: `O-` общие, `G-` Go, `P-` PHP.

## Ключевые принятые

Коротко — то, что роли задевают почти в каждой задаче. Полная история — `core/decisions-log.md`.

| # | Решение | Где записано |
|---|---|---|
| O-4 | Источник и версию Go SDK всегда спрашивать у пользователя (ответ — в `design.md`); PHP — версия из `composer.lock` | `stacks/go/conventions.md` п. 23, `stacks/php/conventions.md` |
| O-7 | Service/Command/Query — только свой домен; 2+ домена → workflow, он берёт репозитории/сервисы любых доменов напрямую | `architecture/layers.md` |
| O-8 | Workflow транзакционен по умолчанию: проверки + все записи в одной транзакции; Go — внутри `txManager.Exec` только репозитории из аргументов | `approaches/patterns/transactions.md` |
| O-9 | Массовые операции, очистка, схема/миграции в БД — только по явному «да» на каждую; stage/prod — никогда | `core/principles.md`, «Действия с БД» |
| O-10 | PUT — полные данные (`required` / `present\|nullable`), частичное обновление не применяется | `regulations/rest-api.md` |
| O-11 | Валидация — только формат (422); доступ — middleware контекста (401/403); сервис получает фильтр и про права не знает | `architecture/layers.md` |
| O-12 | `/dev` только координирует; каждая роль — субагент со свежим контекстом; памятка `checklist.md` — основа разработчика и ревью; у правила одно основное место | `approaches/process/role-chain.md` |
| O-13 | Роли `/dev` — агенты `agents/df-*` с ограниченными инструментами; общие правила — `approaches/process/subagent.md` | `agents/` |
| O-17 | Рефактор/перенос: из легаси — только контракты (URL, ответ, таблицы и значения БД, morph-типы, теги кэша, события, очереди) и бизнес-правила как требования; реализация легаси и расходящийся с правилами сосед — не образец, слой каждой проверки/меры — по правилам стека; ревью проверяет и `threats.md`/`design.md`; отличие от легаси вне контракта — вопрос, только если меняется видимое поведение | `approaches/process/legacy-refactor.md`, `stacks/{php,go}/security.md` («Меры по слоям»), роли |
| O-18 | Доменные инварианты DTO — `{E}DtoValidator` в папке `Validators/` модуля: не сервис (без зависимостей, хранилища, DI); проверки по данным (существование, уникальность, скоуп) — в сервисе/workflow через репозиторий. Go — файл `{entity}_validator.go` в пакете модуля, возвращает ошибки по полям (`map[string]any`), сервис бросает `exception.NewValidationException` | `architecture/layers.md` |
| P-18 | Данные на запись — DTO по всей цепочке (контроллер → сервис/workflow → репозиторий), не массив; в репозиторий — DTO или типизированные аргументы (`createFromDto`, `updateFromDto`, `setDefault(int, bool)`), не массив; колонки — внутри репозитория, модель с casts — `fill()->save()` | `stacks/php/conventions.md` п. 11a |
| P-17 | В Laravel Request нет SQL (`exists:`/`unique:`/модели/`DB::`) | `stacks/php/conventions.md` |
