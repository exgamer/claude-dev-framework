# Бэклог фреймворка

Находки проверок, не внесённые сразу: «было и до правки» из Шага 3а и всё из полной сверки (`skills/dev-rule/SKILL.md`, «Режим полной сверки»), кроме частного правила во фреймворке — его разбирают сразу (`core/rules-evolution.md`, «Как писать правило»). Сюда — чтобы находки не всплывали по одной в каждой следующей правке. Строка живёт, пока правка не внесена; внесённая — удаляется, решение — строкой в `decisions-log.md`. Решённая, но не внесённая — в «Решить» с пометкой «Решено» до внесения; незаконченная правка перед перезапуском сессии — ещё строка «Сейчас: …» в колонке «Варианты / рекомендация» (`skills/dev-rule/SKILL.md`, «Перезапуск сессии»).

Формат строки: `| ID | уровень | где (файл:строка) | суть | что сделать | источник |`; ID — `B-<номер>` («Исправить») или `D-<номер>` («Решить»), уровень — [ОШИБКА]/[ВНИМАНИЕ]/[ИНФО], источник — какая проверка нашла (дата).

Источники базовой сверки 2026-10-20: **G** — граф + `verify-conflicts.md` (23 кандидата), **A** — аудит ролей, загрузки и дублей, **EG** — Go-эталон против правил, **EP** — PHP-эталон против правил.

**Первая очередь** — B-70…B-86 (решения пользователя с разбора лога задачи 2026-10-21): по `/dev-rule`, одним Шагом 3а на пачку, A/B — у помеченных **A/B**. Осталось: B-85, B-86.
