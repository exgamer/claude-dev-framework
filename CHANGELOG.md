# Changelog

Что менялось во фреймворке — кратко, для людей. Подробности и обоснования — `core/decisions-log.md`.

## 2026-10-21
### Добавлено
- A/B на написании кода в проверке после правки (`tools/ab/`): та же задача на версии до и после правки, разработчик → ревью → слепой судья; запускается, когда правка задевает роли, памятки, эталоны или анализаторы.
- Переход состояния (`regulations/entity.md`): своя Command, эндпоинт и метод модели на каждый переход, запись условным UPDATE, сеттера статуса нет, PATCH/PUT статус не принимают; теги `status-set-directly` (PHP), `status-in-update-request`, `state-field-exported` (Go).
- `core/principles.md`, «Инфраструктурный код — один раз»: вторая копия — кандидат на вынос, третья — вынести, готовый компонент — только он; разработчик предлагает перенос в SDK/`mps/core` в итоге задачи.
- `CHANGELOG.md` — краткая история изменений с начала фреймворка; пункт в нём — шаг `/dev-rule` вместе со строкой `core/decisions-log.md`.
- `tools/check/roles.py` — цепочки загрузки каждой роли и их разница с ревизией: потерянный файл — ошибка, ушедший глубже — проверить глазами.
- Самопроверка фреймворка скриптами вместо агентов: `refs.py` (ссылки на пункты и разделы существуют), `tables.py` (формат журнала и бэклога), `codeblocks.py` (синтаксис блоков go/php), `dups.py` (кандидаты в дубли); всё — в Шаге 3а и `/dev-rule audit`.
- Свой Go-анализатор `tools/lint/gocheck` (таймаут пагинатора в `time.<Unit>`, тег `validate` без `binding` — новый тег `validate-tag-ignored`, имена файлов) и правило phpstan `GenericExceptionRule` (встроенные исключения PHP вне тестов и миграций).
- `tools/lint/php_container.py`: PHP-контейнер находится по монтированию проекта или спрашивается и запоминается у разработчика; `install.sh` для PHP-проекта выбирает его сразу.
### Изменено
- Повтор шагов в Service, Command/Query, Workflow — не находка; `duplicated-handler-skeleton` — только инфраструктура, уровни по числу копий.
- Значения входа — в валидаторе DTO, правила состояния — в методах модели; выбора «валидатор или сущность» в `design.md` больше нет.
- `infra-logic-duplicated`: вторая копия — [ИНФО], третья — [ВНИМАНИЕ] (было [ОШИБКА]); тег и `invariants-inline` — в общем каталоге.
- README переписан по правилу «Любой текст для людей»: актуален (анализаторы на проекте, выбор PHP-контейнера, инструменты, `CHANGELOG.md`), без пересказа других файлов.
- `lint.py` в конце полного прогона печатает «Остаток — проверить глазами»; ревьюер `/dev` больше не читает `RULES.md` целиком.
- Имя контейнера `php-8.5` по умолчанию убрано из `lint.py`, `run.sh` и проверок.
### Исправлено
- PHP-эталон: описание `scheduled_at` в ответе тарифа — у архивного остаётся дата, если он ушёл в архив запланированным (было «null»).
- Правила и эталоны приведены к O-25…O-28: модель PHP держит `can*()` и начальное состояние, поля состояния не в `$fillable`; массовый переход одним UPDATE описан в `regulations/entity.md`; `set-default` архивного или отключённого тарифа с флагом — 422 в обоих эталонах; примеры `go-sdk/infra/postgres.md` и дерево `structure.md` — по эталону.
- Анализаторы после прогона на проектах (только чтение): остаток не печатался при находках и печатался после неполного прогона, общий модуль `Domains/Common` считался доменом, тесты попадали под правила слоёв, несуществующая `--base` давала «0 issues».

## 2026-10-20
### Добавлено
- Стенд прогона PHP-эталона `tools/php-check/run.sh` (phpunit + phpstan в docker); правка эталона в `/dev-rule` — с прогоном обоих эталонов.
- Правила анализаторов в эталонах (D-1): Go — `.golangci.yml` (`depguard`, `forbidigo`, `nlreturn`, `revive`), PHP — `phpat` и `phpstan-disallowed-calls`; у каждого правила — доказательство на заведомом нарушении; PHP — phpstan не ниже уровня 5 (`phpstan-errors`).
- `tools/lint/lint.py go|php <проект>` — правила фреймворка на проекте конфигом фреймворка, в проект ничего не кладётся; вызывается в самопроверке разработчика и в ревью (без находок ревьюер глазами проверяет только «Остаток — агенту»); `install.sh` проверяет `golangci-lint` v2.
- Проверки после правки: `links.py` (битые ссылки и орфаны), `tags.py` (теги и уровни), `lint-rules.py` с таблицей `tools/check/lint-proof/RULES.md` («Ловит точно» / «Остаток — агенту»).
- `/dev-rule`: Шаг 3а — фиксированный набор проверок после всей пачки правок, режим `/dev-rule audit` — полная сверка, `core/backlog.md` для находок «было и до правки».
- Правила развития: «Статика первой» (что проверяется механически — ещё и конфигом анализатора, без ухудшения) и самодостаточность (правила и эталоны опираются только на репозиторий, эталон — только `stacks/*/examples/`, ссылки на исходные проекты вычищены).
- Согласование схемы БД: раздел «Схема БД» в `design.md`, без «да» задачи с миграциями не стартуют, тег `schema-not-approved`.
- `usage.py --session` — расход агентов проверок `/dev-rule` с таблицей «По этапам».
- Каталог тегов с уровнями `approaches/process/review-tags.md` — уровень находки только там (O-24); 21 новый тег, уровни части тегов повышены, понижений нет.
### Изменено
- Транзакции (O-8): в workflow, Service и Command обязательна только при больше одного модифицирующего запроса; новый тег `needless-transaction`; в репозитории транзакции нет.
- Go SDK (O-4): источник и версии — из `go.mod` без вопроса; вопрос — для нового проекта, нового пакета `gosdk-*` или смеси GitLab/GitHub; справочник разбит на `reference/gitlab/` и `reference/github/`.
- Workflow: не вызывает другой workflow (оба стека), только для 2+ доменов, может содержать логику агрегата и свои интерфейсы-зависимости; путь Go — `internal/workflows/{domain}/{module}/` (предварительно).
- Go: интерфейсы-зависимости модуля — файлы групп `repository.go`, `tx_manager.go`, `modules.go`, `system.go` (G-6); узкие интерфейсы с `-er` допустимы; интерфейс сервиса — по необходимости (PHP — `ServiceInterface` всегда).
- Порты внешних систем и адаптеры называются по роли (`…Repository`, `…Notifier`) вместо PHP `…Gateway`; теги `gateway-*` заменены, эталоны переименованы.
- Доступ — в транспорте, скоуп — обязательным аргументом сервиса и репозитория; строгое тело запроса (415/400/413); права маршрутов — на группу модуля.
- PHP-списки: форма пагинации — вопрос на задаче (mps/core `search()` или `Page`, рекомендация — `Page`, P-22 — тестовый вариант); формат ответа — как в Go SDK (`items` + `pagination`), тег `pagination-format`.
- PHP: Command/Query — простой `final` класс с `execute(...)` без базового класса ядра; `api.response` — первым middleware группы; `404` в OpenAPI — только у поиска по ID; `Core/definitions.php` — только для технических библиотек.
- Регламенты по сверке: URL `/api/<context>/v1/<domain>/<entity>`, id ≤ 0 и не число — 422, `per_page` по умолчанию 30, деньги — целым числом в минимальных единицах.
- Go: контекст `consumer` для событий брокера, консоль и миграции (`entrypoints/system/console`, `internal/migrations/`), Sentry — через `errorreporter` и `SentryKernel`, HTTP-адаптер — статус ответа проверяется всегда (`http-status-unchecked`).
- Роли: архитектор не читает `decisions-log.md`, разработчик и ревьюер читают `structure.md` и эталон по своим слоям; унаследованное нарушение — [ВНИМАНИЕ] «унаследовано», попутно не исправляется; «принять риск» гонки — вопрос пользователю.
- Стиль: «4+ аргумента → `Params`» — не для конструкторов, `ctx` не в счёт; комментарии к полям — только у неочевидных.
### Исправлено
- Go: правила валидации — в теге `binding:"…"` (правила в `validate` молча не проверялись); в эталоне `SetTimeout(10*time.Second)` давал переполнение и 500 на списке.
- Эталоны Go и PHP приведены к правилам по полной сверке: частичный уникальный индекс тарифа по умолчанию, OpenAPI 401/403/404, DTO интеграций, тесты на ветки ошибок.
- Правила приведены к эталонам и SDK: порядок аргументов `NewConsumerTopicDurableConfig`, контекст `internal` в Go недопустим, доставка outbox — Command домена, путь unit-теста PHP — полностью как у класса.
- Убрано добавленное без решения правило «запись по id после чтения со скоупом — без скоупа» (ослабляло проверку); `graph.py` больше не теряет узлы в кэше.
