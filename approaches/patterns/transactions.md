# Транзакции

## Когда транзакция обязательна (решение O-8, пересмотр 2026-10-20)

Одно правило для workflow, сервиса и Command домена: транзакция ставится там, где она аргументирована, а не по слою.

- **Обязательна — когда сценарий делает больше одного модифицирующего запроса**: в разные таблицы (тариф + строка outbox) или отдельными запросами в одну таблицу (снять флаг «по умолчанию» со старого тарифа и поставить новому — два `UPDATE`); через разные репозитории/сервисы или несколько методов одного репозитория подряд — одинаково. Частичный результат недопустим.
- **Не нужна** — один модифицирующий запрос (один `INSERT`/`UPDATE`/`DELETE`, в т. ч. массовый `UPDATE … WHERE`) и только чтение; исключение — транзакция ради блокировки (ниже, «Проверки перед записью»). Обоснования не требуется. В PHP одиночный `create`/`update`/`delete` `CRUDService` и так обёрнут ядром — это не повод добавлять свою.
- **Основание пишется в `design.md`**, раздел «Границы транзакций»: по каждому сценарию (workflow, Command, Service) с транзакцией — какие модифицирующие запросы (таблицы) в неё входят; как проверка перед записью защищена от гонки (`concurrency.md`: индекс, условие в `UPDATE`, внешний ключ, блокировка); какие побочные эффекты — после коммита. Сценарий с одним модифицирующим запросом без блокировки в разделе не пишется.
- **Проверки перед записью в транзакцию автоматически не тянутся.** Транзакция даёт атомарность записей, но не защищает проверку от параллельного изменения (READ COMMITTED). Гонка «проверил — записал» закрывается по `concurrency.md`: уникальный индекс, условие в `UPDATE … WHERE`, внешний ключ на существование связанной записи; блокировка (`FOR SHARE`/`FOR UPDATE`) — только там, где ограничением БД не обойтись. Блокировка живёт только внутри транзакции — тогда транзакция ставится ради неё, основание — раздел «Конкурентность» `design.md`.
- **Данные внешней системы** (лимит цены из реестра, ответ партнёра) читаются **до** транзакции: HTTP в транзакции запрещён («Общее»).
- Между шагами внешний вызов или публикация — запись в БД (в транзакции, если запросов больше одного), доставка наружу — через outbox (`outbox.md`) или сага с компенсацией.
- Массовая обработка — транзакция на пачку, а не на весь прогон.
- Больше одного модифицирующего запроса без транзакции — тег `multi-write-without-transaction` (для workflow, сервиса и Command одинаково). Транзакция вокруг одного модифицирующего запроса без блокировки по `concurrency.md` — тег `needless-transaction`: убрать. Уровни — каталог тегов (`approaches/process/review-tags.md`).

## Общее

- **Где открывать:** на уровне, который принимает решение о сценарии, — workflow или сервис/Command своего модуля. Не в репозитории — метод репозитория делает один запрос (`architecture/layers.md`, `repository-multi-query`), своей транзакции у него нет; не в контроллере/хендлере.
- **Чем:**
  - Go — `gosdk-db-core/pkg/transaction` (`Manager*`), интерфейс `TxManager` объявляет потребитель. Менеджер пересобирает на `tx` **только репозитории** — внутри `fn` нельзя вызывать сервис или Command домена: их репозитории на пуле, запись уйдёт мимо транзакции (тег `tx-bypassed-by-service`, `stacks/go/review-tags.md`). Workflow пишет через репозитории (O-7). Подробно — `stacks/go/go-sdk/infra/postgres.md`.
  - PHP — `TransactionManagerInterface::run(callable)`; биндинг `DatabaseTransactionManager`, в тестах `NoopTransactionManager` (`mock` в `definitions.php`). Не `DB::transaction` в сервисе, Command и workflow; `DB::transaction` напрямую — только в реализации менеджера транзакций (`DatabaseTransactionManager` в `Infrastructure/`); настройка уровня БД в транзакции (`SET LOCAL`) — там же, в отдельном варианте менеджера, не в репозитории (`stacks/php/mps-core/transactions.md`). Транзакция на соединении — сервисы домена внутри `run()` в неё попадают (вложенные — savepoint). Подробно — `stacks/php/mps-core/transactions.md`.
- **Внутри транзакции нет побочных эффектов:** HTTP во внешние системы, публикация в брокер, файлы, `dispatch`, инвалидация кэша — после коммита. Нужна гарантия доставки события вместе с записью → outbox.
