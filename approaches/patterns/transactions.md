# Транзакции

## Workflow — транзакционен по умолчанию (решение O-8)

Workflow — агрегат над доменами, его граница = граница согласованности. Поэтому:

- **Всё, что workflow пишет, и всё, что он читает для решения о записи, — в одной транзакции.** Проверка «парковка существует/активна» → запись тарифа: и проверка, и запись внутри транзакции.
- Workflow без транзакции — только с причиной в разделе «Границы транзакций» `design.md`:
  - workflow только читает;
  - между шагами внешний вызов или публикация — запись в БД в транзакции, доставка наружу через outbox (`outbox.md`) или сага с компенсацией;
  - массовая обработка — транзакция на пачку, а не на весь прогон.
- Транзакция даёт атомарность, но не защищает проверку от параллельного изменения (READ COMMITTED). Проверяемые данные могут измениться параллельно и это важно → блокировка (`FOR SHARE`/`FOR UPDATE`) или условная запись по `concurrency.md`. Нужна ли — решение в `design.md`.
- Workflow с записью без транзакции и без причины в `design.md` — **[ОШИБКА]** (тег `workflow-without-transaction`).

## Service, Command/Query домена

- **Когда:** сценарий делает 2+ записи, и частичный результат недопустим (создать запись + обновить связанную). Одиночный `Create`/`Update`/`Delete` транзакцию не требует.
- Отсутствие транзакции в мульти-записи — **[ОШИБКА]** (тег `multi-write-without-transaction`).

## Общее

- **Где открывать:** на уровне, который принимает решение о сценарии, — workflow или сервис/Command своего модуля. Не в репозитории, не в контроллере/хендлере.
- **Чем:**
  - Go — `gosdk-db-core/pkg/transaction` (`Manager*`), интерфейс `TxManager` объявляет потребитель. Менеджер пересобирает на `tx` **только репозитории** — внутри `fn` нельзя вызывать сервис или Command домена: их репозитории на пуле, запись уйдёт мимо транзакции (**[ОШИБКА]**, тег `tx-bypassed-by-service`). Workflow пишет через репозитории (O-7). Подробно — `stacks/go/go-sdk/infra/postgres.md`.
  - PHP — `TransactionManagerInterface::run(callable)`; биндинг `DatabaseTransactionManager`, в тестах `NoopTransactionManager` (`mock` в `definitions.php`). Не `DB::transaction`. Транзакция на соединении — сервисы домена внутри `run()` в неё попадают (вложенные — savepoint). Подробно — `stacks/php/mps-core/transactions.md`.
- **Внутри транзакции нет побочных эффектов:** HTTP во внешние системы, публикация в брокер, файлы, `dispatch`, инвалидация кэша — после коммита. Нужна гарантия доставки события вместе с записью → outbox.
