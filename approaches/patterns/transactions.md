# Транзакции

- **Когда:** сценарий делает 2+ записи, и частичный результат недопустим (создать запись + обновить связанную, запись в 2 домена). Одиночный `Create`/`Update`/`Delete` транзакцию не требует.
- **Где открывать:** на уровне, который принимает решение о сценарии, — workflow (для нескольких доменов) или сервис (для своего модуля). Не в репозитории, не в контроллере/хендлере.
- **Чем:**
  - Go — `gosdk-db-core/pkg/transaction` (`Manager*`), интерфейс `TxManager` объявляет потребитель. Подробно — `stacks/go/go-sdk/infra/postgres.md`.
  - PHP — `TransactionManagerInterface::run(callable)`; биндинг `DatabaseTransactionManager`, в тестах `NoopTransactionManager` (`mock` в `definitions.php`). Не `DB::transaction`. Подробно — `stacks/php/mps-core/transactions.md`.
- **Внутри транзакции нет побочных эффектов:** HTTP во внешние системы, публикация в брокер, файлы, `dispatch` — после коммита. Нужна гарантия доставки события вместе с записью → outbox.
- Отсутствие транзакции в мульти-записи — **[ОШИБКА]** на ревью.
