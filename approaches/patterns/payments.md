# Платежи и колбэки шлюзов

Общие правила для любого платёжного пути — хендлер колбэка, workflow оплаты/возврата, consumer события оплаты. Повод — прод-инциденты Go-сервиса и security-аудит PHP-монолита (`stacks/go/review-findings.md`, «Платёжные хендлеры»; `stacks/<stack>/review-findings.md`, «Безопасность»). На ревью каждый пункт проверяется явно и пишется в отчёт, даже если нарушений нет (`review.md`, шаг 6).

| Правило | Почему | Тег |
|---|---|---|
| **Идемпотентность** по `(payment_system, payment_system_txn_id)` или внешнему id события: уникальный индекс в БД, повтор возвращает прежний результат, не вторую запись (`idempotency.md`) | повторный или параллельный колбэк шлюза = двойное списание | `missing-idempotency` |
| **Подпись колбэка проверяется до любого изменения состояния**, по протоколу именно этого шлюза; сравнение в постоянное время | статус и сумма из тела без подписи — чужая оплата «проведена» | `unverified-webhook` |
| **Сумма, валюта, статус — с сервера**: сверяются с заказом/сессией, не берутся из запроса как истина | подмена суммы в колбэке | `broken-access-control` |
| **Переход статуса — условный** (`WHERE status = :expected`) или под блокировкой; финальный статус не перезаписывается (`concurrency.md`, `race-on-status`) | два колбэка подряд, возврат поверх оплаты | `race-on-status` |
| **Ответы шлюза не кэшируются, если это ошибка**; кэш — только успешных ответов | закэшированный фейл отдаётся шлюзу вечно | `cache-stores-errors` |
| **Побочные эффекты после фиксации платежа** — через outbox и отдельный обработчик, не fire-and-forget после INSERT (`outbox.md`, `async.md`) | упал процесс — ЛПМ не узнал об оплате, чека нет | `side-effect-without-outbox` |
| **Платёж без связанной сущности** (`session_id = 0`, пустой `order_id`) отсекается до записи | FK violation и 500 на колбэке | `payment-without-parent` |
| **У каждого нового статуса платежа есть потребитель** — крон, consumer, переход в workflow; показать его в MR (`impact-analysis.md`) | статус без обработчика — тупик навсегда | `status-without-consumer` |
| **Соседний шлюз — не образец молча**: новый шлюз сверяется с уже существующим шлюзом проекта (в parking — `kassa24`) по подписи, кэшу, скоупу; расхождение — почти всегда баг копирования | второй шлюз скопировали до того, как в первом добавили проверку | — |
| **Секреты шлюза** — из конфига/vault; в БД — зашифрованными; в логах и общем Redis их нет (`security.md`) | доступ к Redis = подделка колбэков | `hardcoded-secret`, `sensitive-data-in-logs` |
| **Тест на каждый платёжный сценарий** — e2e по шлюзам (`tests/<шлюз>/` в Go, `tests/Feature/…` в PHP), включая повтор колбэка и колбэк с неверной подписью (`testing.md`) | платёжный путь без теста — законное замечание | — |

Чувствительная зона «деньги» в `design.md` → обязателен `/dev-security design` (`approaches/process/security.md`): угрозы и меры из таблицы попадают в `threats.md` строками `Th*`, разработчик реализует их как критерии готовности.
