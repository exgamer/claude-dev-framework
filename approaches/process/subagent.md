# Правила субагента `/dev`

Общие для всех агентов `agents/df-*.md`. Роль, запущенная пользователем напрямую (`/dev-go`, `/dev-review`…), работает по своему `SKILL.md` в текущей сессии — этот файл к ней не относится.

- `{DF}` — `.claude/dev-framework` в проекте, если есть, иначе `~/.claude/dev-framework`.
- Ты в свежем контексте и не видел разговора с пользователем. Всё, что нужно, — в поручении оркестратора и в артефактах `docs/tasks/<ключ>/`. Чего там нет — не додумывай: верни вопросом.
- **Пользователю вопросы не задаёшь.** Возвращаешь их оркестратору списком: вопрос, 2–3 варианта, рекомендация. Новый вопрос по ходу — по политике из поручения: (а) решаешь по рекомендации и возвращаешь строку для лога; (б) откладываешь затронутый кусок. Согласования до кода и изменение внешнего контракта — всегда откладываешь.
- **`rules-log.md` не правишь** — возвращаешь строки для него (тип, где, суть, предложение «фреймворк / проект / оставить»).
- Пишешь только свои артефакты и файлы своей задачи из поручения. Чужие файлы, `plan.md` (кроме своей роли), правила фреймворка — не трогаешь.
- Коммит, пуш, действия с БД из `core/principles.md` («Действия с БД») — не выполняешь, возвращаешь вопросом. В коде и черновиках коммитов/MR — без подписей Claude/ИИ (`core/principles.md`, «Git»).
- **Git — только чтение:** `status`, `diff`, `log`, `show`. Не выполняешь ничего, что меняет индекс, дерево или историю: `add`, `commit`, `checkout`, `restore`, `stash`, `reset`, `rm` (и `--cached`), `mv`, `clean`, `switch`, `merge`, `rebase` — даже для своего файла и «пробно» (`-n`). Откатить свою правку — снова через `Edit`/`Write`.
- **Временные файлы** (скрипты, выгрузки) — в каталоге для временных файлов сессии с префиксом своей задачи (`a15bw-probe.php`, `rw8-sql.txt`): каталог общий для всех агентов сессии, файл без префикса перезапишет соседний. Свои временные файлы удаляешь сам; не можешь удалить — путь в итог.
- **Разработчик:** из `design.md` читаешь разделы из колонки «контекст» своей задачи и «Контракты слоёв»; правила — база стека и файлы из «контекста» (по ходу можно добавить нужное — памятка главнее списка). Код других слоёв и задач — только интерфейсы, DTO и сигнатуры, без реализации. В контракте не хватает метода/поля — не добавляешь сам в чужой слой и не обходишь: вопрос оркестратору. Задача по факту больше предела (`planning.md`, «Размер задачи»: файлы/слои или больше ~120 шагов) — не дотягиваешь: доделываешь законченную часть (собирается, тесты зелёные) и возвращаешь предложение разреза остатка.
- **Разработчик: прогон в самопроверке — только по своей задаче** (`tools/lint/lint.py --base` смотрит дифф всего дерева — находки в чужих файлах не свои, их не исправлять) (QA в режиме `tests` гоняет всё — по `skills/dev-qa`, когда разработчики не работают): рядом в том же дереве работают другие агенты, полная сборка может упасть на их недописанных файлах. Go — `go build`/`go vet`/`go test` по своим пакетам (`./internal/domains/billing/tariff/...`), `gofmt -l` по своим файлам; PHP — `phpstan` и тесты по своим путям, `csfix` по своим файлам. Вывод тестов — короткий: PHPUnit с `--no-progress`, наружу только итог (`… | tail -3`); Go — `go test` без `-v`. Полный вывод — только упавшего теста и только по своему файлу. Полный прогон делает оркестратор (`planning.md`, «Команда»). Чужое красное в своих пакетах (сломан контракт волны 0) — вопрос, не правка.
- **Навигация по коду** — `code-navigation.md`: IDE (`mcp__idea__*`), если проект открыт в IDEA, иначе grep; строковые связи и использования — всегда grep. Объявления и сигнатуры — через индекс IDE; файл целиком читаешь, только когда нужна его реализация. В итоге строка `навигация: IDE` / `навигация: grep (<причина>)` и число файлов, прочитанных целиком.
- **Чтение пакетами** — независимые чтения и поиски (файлы правил, файлы кода, grep) — в одном шаге параллельными вызовами, не по одному: каждый шаг заново проходит весь накопленный контекст.
- **Итог оркестратору — не длиннее 15 строк**: что сделано (файлы/артефакты), как проверено, вопросы, строки для `rules-log.md`, что отложено. Подробности — в артефакт, не в итог. Состав поручений, итогов и артефактов — по шаблонам процессов, полностью (ссылки R*/AC*/T*, таблицы, разделы); правило `core/style.md`, «Любой текст для людей» — о тоне и лишних словах в том, что уходит в код, Swagger, коммиты, MR и в вопросы пользователю, состав обмена между ролями оно не сокращает.
