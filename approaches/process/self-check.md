# Самопроверка перед сдачей

Разработчик проходит перед тем, как отдать работу ревьюеру. Сначала — памятка стека `stacks/<stack>/checklist.md` по каждому пункту, который задевает код; здесь — только то, что относится к процессу.

- [ ] Код соответствует `design.md`; если отступил — `design.md` обновлён.
- [ ] Каждый новый файл лежит по `stacks/<stack>/structure.md`, имя — по правилам стиля.
- [ ] Прочитан соседний модуль того же типа — форма повторена.
- [ ] Карта связей: по каждому изменённому символу, роуту, событию, таблице, значению enum повторён поиск использований (имя + строковый литерал); всё «меняется вместе» изменено, «сохраняется» — не сломано.
- [ ] Нет недописанного: добавленные импорты/поля/зависимости действительно используются (grep по вызовам, а не только по импорту), особенно если задачу прерывали другим запросом.
- [ ] Ни одного пробела/спора не решено молча; каждый случай, отступление и решение по ходу — строкой в `docs/tasks/<ключ>/rules-log.md`.
- [ ] Новая логика покрыта unit-тестами (правила R*, ветки ошибок, кейсы `qa.md` уровня unit) по `approaches/process/testing.md`: без БД/HTTP, фейки только на границе.
- [ ] Прогнаны сборка, линтер, тесты стека — с выводом. Не запускал — так и написано.
  - Go-код с горутинами или общим состоянием — `go test -race ./...`.
  - Уязвимости зависимостей, если инструмент есть: Go — `govulncheck ./...`, PHP — `composer audit`.
  - Go: `go build ./... && go vet ./... && go test ./... && gofmt -l .` (с `vendor/` — `gofmt -l main.go cmd internal pkg`)
  - CI проекта без гейтов (pipeline — только containerize + deploy, ни lint, ни test stage) — локальный прогон единственный гейт; его результат — в отчёт явно.
  - PHP: `composer csfix-validate`, `composer phpstan`, `composer test:run` (или их аналоги из `composer.json`)
- [ ] Правила фреймворка анализаторами — `python3 {DF}/tools/lint/lint.py <go|php> <корень проекта> --base <база>` (PHP — ещё `--sub <подпроект>`, `--container <PHP-контейнер>`; база — `git merge-base HEAD origin/<ветка, от которой начата задача>`, по `regulations/git.md` — `release`: разработчик смотрит своё от точки ответвления; ревьюер — от целевой ветки MR, `stage`, `review.md`): конфиг фреймворка, в проект ничего не кладётся (`{DF}/tools/lint/README.md`). Каждая находка в своём коде исправлена **до сдачи** — сдать с находкой нельзя; вывод — в отчёт. Находки в чужих файлах (рядом работают другие агенты) и старые нарушения в нетронутых строках задетого файла (PHP проверяет файл целиком) — не исправлять, а назвать в отчёте «унаследовано». Анализатор — дополнение к памятке, не замена: она проходится целиком. Инструмент не запустился (нет `golangci-lint` v2, нет контейнера, упал) — так и написано, а правила из `{DF}/tools/check/lint-proof/RULES.md` проверены по памятке глазами, как раньше.
- [ ] Для проверки на живой инфраструктуре — использованы уже поднятые общие контейнеры (`docker ps`), одноразовые не поднимались; тестовые данные удалены.
- [ ] Массовые операции, очистка, создание и изменение схемы БД (миграции) — не выполнялись без явного «да» на каждую (`core/principles.md`, «Действия с БД»).
- [ ] Пройдена памятка стека (`stacks/<stack>/checklist.md`), включая транзакции, конкурентность, производительность, безопасность.
- [ ] Прогнан grep на запросы к БД вне репозитория по своим файлам (`stacks/<stack>/review-checks.md`, проверки за пределами дифа, п. 0) — пусто.
- [ ] Прогнан grep на повторённую обработку формата (там же, п. 0a) — своих inline-преобразований нет, всё через SDK или хелпер проекта.
- [ ] Swagger обновлён при изменении API; новые env описаны; нет отладочного кода и посторонних изменений.
- [ ] Ветка/коммиты — по `regulations/git.md`; коммит и пуш — только после подтверждения пользователя.
- [ ] Тексты для людей — комментарии, docblock, Swagger, сообщения ошибок, сообщение коммита, описание MR — по `core/style.md`, «Любой текст для людей»: по делу, без «ИИ-воды».
