# Самопроверка перед сдачей

Разработчик проходит перед тем, как отдать работу ревьюеру.

- [ ] Код соответствует `design.md`; если отступил — `design.md` обновлён.
- [ ] Каждый новый файл лежит по `stacks/<stack>/structure.md`, имя — по правилам стиля.
- [ ] Прочитан соседний модуль того же типа — форма повторена.
- [ ] Карта связей: по каждому изменённому символу, роуту, событию, таблице, значению enum повторён поиск использований (имя + строковый литерал); всё «меняется вместе» изменено, «сохраняется» — не сломано.
- [ ] Нет недописанного: добавленные импорты/поля/зависимости действительно используются (grep по вызовам, а не только по импорту), особенно если задачу прерывали другим запросом.
- [ ] Ни одного пробела/спора не решено молча; каждый случай, отступление и решение по ходу — строкой в `docs/tasks/<ключ>/rules-log.md`.
- [ ] Новая логика покрыта unit-тестами (правила R*, ветки ошибок, кейсы `qa.md` уровня unit).
- [ ] Прогнаны сборка, линтер, тесты стека — с выводом. Не запускал — так и написано.
  - Go-код с горутинами или общим состоянием — `go test -race ./...`.
  - Уязвимости зависимостей, если инструмент есть: Go — `govulncheck ./...`, PHP — `composer audit`.
  - Go: `go build ./... && go vet ./... && go test ./... && gofmt -l internal pkg`
  - PHP: `composer csfix-validate`, `composer phpstan`, `composer test:run` (или их аналоги из `composer.json`)
- [ ] Для проверки на живой инфраструктуре — использованы уже поднятые общие контейнеры (`docker ps`), одноразовые не поднимались; тестовые данные удалены.
- [ ] Пройден `stacks/<stack>/review-findings.md` и `approaches/patterns/performance.md` (запросы, N+1, индексы, кэш), `approaches/patterns/concurrency.md` (гонки, data race).
- [ ] Swagger обновлён при изменении API; новые env описаны; нет отладочного кода и посторонних изменений.
- [ ] Ветка/коммиты — по `regulations/git.md`; коммит и пуш — только после подтверждения пользователя.
