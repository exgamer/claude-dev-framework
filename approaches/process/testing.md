# Тесты: что, кто и как

Общие правила для обоих стеков. Раскладка файлов и инструменты — `stacks/<stack>/structure.md`, «Тесты» (Go — рядом с кодом, PHP — `tests/Unit|Feature/{Подпроект}/…`, O-3), прогон — `self-check.md`. Как писать на классах ядра PHP — `stacks/php/mps-core/tests.md`.

## Уровни

| Уровень | Что проверяет | Кто пишет | Когда | Без чего |
|---|---|---|---|---|
| unit | правило R*, ветку ошибки, инвариант валидатора, маппер, хелпер — через публичный метод класса | разработчик, вместе с кодом | в задаче `plan.md`, до сдачи | БД, HTTP, очередь, файловая система, контейнер приложения (PHP — `PHPUnit\Framework\TestCase`, не `Tests\TestCase`, если контейнер не нужен) |
| интеграционный | репозиторий на живой БД, consumer на живой очереди, несколько процессов/реальная ФС | QA (`/dev-qa tests`), разработчик — для своего репозитория | после кода и регистрации (волна 4 `plan.md`), до ревью | моков: это проверка реальной инфраструктуры; Go — `//go:build integration`, PHP — `tests/Feature` или `#[Group('integration')]` |
| e2e / feature | сценарий через HTTP от запроса до БД: критерий приёмки AC* целиком, негативные кейсы `threats.md`, регрессия по связям «сохраняется» | QA | после кода и регистрации (волна 4 `plan.md`), до ревью | — |
| разовая проверка | кейс, который нельзя закрепить тестом в репозитории (правило ниже) | QA | когда есть что проверять, до ревью | изменений рабочего дерева и git задачи |

Кейсы (`qa.md`) пишутся **до кода** по AC*, S*.a, R*, Th*, C* (`analysis.md`, `role-chain.md`); каждый кейс получает уровень из таблицы, разработчик покрывает unit-кейсы своей задачи, QA — остальные.

## Правила

- **Тест на правило, не на реализацию.** Имя теста — правило или сценарий (`test_update_without_present_field_returns_422`, `TestCreateTariff_ParkingNotFound`), не имя метода. Проверяется результат и видимое поведение (ответ, запись, событие), не порядок внутренних вызовов.
- **Моки и фейки — только на границе:** репозитории, адаптеры внешних систем (порты `…Repository`/`…Notifier`), шина, `Clock`/UUID, менеджер транзакций (Go — `testsupport/txfakes`, PHP — `NoopTransactionManager` через `mock` в `definitions.php`). Бизнес-сервисы, валидаторы, мапперы не мокаются (`regulations/contracts.md`, «Моки в тестах»; PHP-исключение — там же). Предпочтение — in-memory фейк по интерфейсу, а не mock с ожиданиями вызовов.
- **Unit-тест детерминирован и изолирован:** нет общего состояния между тестами, время и случайность — через зависимость, не `now()`/`rand()` внутри.
- **Конкурентные места** из «Конкурентность» `design.md` — интеграционный тест с параллельными запросами или повторной доставкой на реальной БД (`approaches/patterns/concurrency.md`); unit здесь ничего не доказывает.
- **Баг-фикс** — тест бага пишется до правки и падает на коде до неё, затем проходит и остаётся в наборе (`bugfix.md`, «Шаги», п. 2 и «Проверка до правки»); причина в условии запроса, а БД в окружении нет, — исключение из уровней выше: тест репозитория с моком построителя, проверяющий условие (там же).
- **Рефактор и перенос** — характеризующие тесты на сохраняемый контракт до правок кода, зафиксированные доказуемо (коммит с подтверждения, хэш файлов или прогон на базовой ветке) (`legacy-refactor.md`, п. 2). Технический компонент без контракта — тесты нового кода на функциональность, легаси не импортируют.
- **Связь «проверено, не затронута»** проверяется разово на ревью (`git diff` по путям), не постоянным автотестом «легаси по-прежнему вызывает легаси»; на связь «сохраняется» — регрессионный тест (`impact-analysis.md`).
- **Данные тестов:** большие фикстуры — разреженный файл или поток, не строка в памяти; тестовые записи в общей БД удаляются после прогона; тесты, пересоздающие схему или пишущие в общую БД разработки, — только с «да» пользователя (`core/principles.md`, «Действия с БД»).
- **Архитектурный тест границ `Common`** (`architecture/layers.md`, «Общий бизнес-словарь») — обычный unit-тест без новых зависимостей: проходит по файлам `Common` и падает на запрещённом — импорт из доменов, Infrastructure, Workflow, точек входа и фреймворка (PHP — `Illuminate\`, кроме базового трейта enum ядра; Go — всё, кроме стандартной библиотеки и самого `internal/common/`), конструктор с зависимостями (PHP). Пишется в задаче, где `Common` появляется в проекте впервые (архитектор ставит его в волну 0), дальше живёт в наборе тестов; где лежит — «Тесты» в `structure.md` стека.
- **Разовая проверка** — только для кейса, который нельзя закрепить тестом в репозитории (перенос между копиями кода, где тест сделал бы копии разными; поведение прежней версии пакета SDK при выпуске): временный тест во временной копии дерева (копия файлов в scratchpad; рабочее дерево и git задачи не меняются), прогон — с выводом в `qa.md`, копия удаляется. Не замена постоянному тесту: можно закрепить — закрепляется; критерий приёмки закрывается разовой проверкой, только если в `qa.md` записано, почему постоянный тест невозможен; характеризующие тесты рефактора и переноса — всегда постоянные (`legacy-refactor.md`, п. 2); связь без постоянного теста — строкой в «Отложено» итога.
- **Инфраструктура для прогона** — уже поднятые общие контейнеры (`docker ps`), одноразовые не поднимаются.
- **Падение теста из-за окружения** (нет `APP_URL`, не поднята БД) — не сигнал о коде, но и не «зелёный»: в итоге пишется, что не запускалось и почему (`core/principles.md`, «Честность результата»).
- Тесты — тоже код: правила формы (`core/style.md`) действуют, кроме data provider и описаний моков, где форму задаёт фреймворк тестов. Комментарии-пересказы шагов не пишутся.

## Готовность

Когда тестов достаточно — `role-chain.md`, «Definition of Done» (критерии приёмки, unit-тесты автора, меры `threats.md`, регрессия по связям, полный прогон).

Ревью проверяет тесты вместе с кодом: тест, который проверяет только «метод вызван», или сценарий без теста при живых тестах в проекте, разовая проверка без причины в `qa.md` — замечание (`review.md`; тег — как у сценария без теста).
