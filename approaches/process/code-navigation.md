# Навигация по коду: IDE, иначе grep

Цель — меньше читать код целиком. Если открыта IDEA с MCP-сервером (`idea`), часть вопросов к коду решается через её индекс — точно и без чтения файлов. Нет IDE — работа как раньше, grep и чтение файлов. Оба режима равноправны по результату: IDE экономит контекст, но не отменяет ни одной проверки.

## Выбор режима

Каждый агент решает сам, при первом обращении к коду:

1. Есть инструменты `mcp__idea__*` → вызов `search_symbol` с `projectPath` = корень проекта задачи (абсолютный путь).
2. Ответ пришёл → **режим IDE**.
3. Инструментов нет, ошибка соединения или ответ «Unable to determine the target project» (проект не открыт в IDEA; в ответе список открытых) → **режим grep** до конца задачи. Не переспрашивать и не пробовать снова.
4. IDE посреди задачи отвечает ошибкой или явно неполно (не нашла символ, который виден в файле) → режим grep до конца задачи.
5. В итоге одной строкой: `навигация: IDE` или `навигация: grep (<причина>)`.

## Проверка при старте и предложение включить

Делает тот, кто говорит с пользователем: оркестратор `/dev` (Фаза 0) и роли, которые читают код и запущены напрямую: `/dev-go`, `/dev-php`, `/dev-architect`, `/dev-review`, `/dev-mr`. Остальные (`/dev-analyst`, `/dev-qa`, `/dev-security`) при старте не проверяют: IDE используют, если она доступна, иначе grep. Субагенты не спрашивают — у них только выбор режима выше.

Проверка — `search_symbol` с `projectPath` = корень проекта и любым именем из проекта:

| Результат | Что сказать пользователю |
|---|---|
| ответ пришёл | одной строкой: `навигация: IDE` |
| инструментов `mcp__idea__*` нет или ошибка соединения | IDE недоступна, работа пойдёт через grep (больше чтения файлов). Включить: (1) IDEA → Settings → Tools → MCP Server → Enable MCP Server; (2) если сервер ещё не добавлен — `claude mcp add --transport http --scope user idea http://127.0.0.1:64342/stream`; (3) `/mcp` → переподключить `idea`. Шаги — README, «Установка», шаг 5 |
| «Unable to determine the target project» | проект не открыт в IDEA (в ответе — список открытых): открыть `<корень проекта>` в IDEA, переподключать ничего не нужно |

Предложение не останавливает работу: сказать и продолжать на grep. В `/dev` — строкой в начале разведки и пунктом в общем списке вопросов («IDE недоступна — включить до разработки? Рекомендация: да»); перед первой задачей разработки — проверить ещё раз: включили — разработчики и ревьюер работают через IDE. Проверку не повторять больше одного раза и не спрашивать снова, если пользователь ответил «без IDE».

## Что через IDE

Проверено на IDEA 2026.2.3: `search_symbol`, `get_symbol_info` — PHP-проект и Go (`stacks/go/examples/tariff`); `search_structural`, `lint_files` — PHP, на Go-проекте ещё не проверялись, режим grep для этого вопроса:

| Вопрос | Инструмент | Вместо |
|---|---|---|
| Где объявлен тип/функция/метод | `search_symbol` (`q` — имя или часть; `paths` — сузить) → файл и строки начала/конца объявления | grep по имени (ловит и вызовы, и строки) |
| Сигнатура, что реализует, какие исключения бросает | `get_symbol_info` (`filePath`, `line`, `column` — из `search_symbol`) | чтение файла целиком |
| Тело одного метода/типа | `Read` с `offset`/`limit` по строкам из `search_symbol` | чтение файла целиком |
| Вызовы по форме кода без комментариев и строк (PHP) | `search_structural` (`$s$->create($a$)`, `fileType: PHP`, `directoryToSearch`) | grep по `->create(` |
| Ошибки и предупреждения инспекций в своих файлах | `lint_files` (`min_severity: WARNING`) | — (дополнение к линтеру стека, не замена) |

Правило «верхний слой читает только интерфейсы и DTO нижнего» (`subagent.md`) в режиме IDE — это `search_symbol` + `get_symbol_info`, без чтения реализаций.

**Файл целиком — только ради реализации.** Где объявлено, какая сигнатура, что бросает, что реализует — индекс IDE и чтение по строкам (`Read` с `offset`/`limit`); весь файл — когда нужна логика целиком (переносимый метод легаси, правка своего файла). В итоге агента — число файлов, прочитанных целиком. Почему: каждый шаг агента заново читает весь контекст, прочитанный целиком файл оплачивается на всех следующих шагах (mobile-api-rewrite: при подключённой IDE агенты работали через полное чтение, 96% токенов — повторное чтение контекста).

## Что всегда grep

- **Кто вызывает метод / все использования символа.** Иерархия вызовов IDE (`analyze_calls`) для Go и PHP не работает (находит только Java-символы) — использования ищутся grep по имени и FQCN/интерфейсу, как в `impact-analysis.md`. `search_structural` в PHP сужает шум, но тип получателя не проверяет.
- **Строковые связи** — их не видит ни один индекс: биндинги DI (`definitions.php`, `*_factory.go`), имена роутов и прав, имена событий/очередей, литералы enum и статусов, ключи кэша, колонки в raw SQL, конфиг (`impact-analysis.md`, «Неявные»).
- Справочники SDK `reference/` — grep, как раньше (`skills/dev-go`, Шаг «Что уже есть в SDK»).

## Чего через IDE не делать

Разрешены только чтение и анализ: `search_symbol`, `get_symbol_info`, `search_structural`, `lint_files` — они и выданы агентам `df-*`. Остальные инструменты сервера `idea` агентам не выдаются и вручную не вызываются:
- правка кода (`apply_patch`, `create_new_file`, `rename_refactoring`, `reformat_file`, `apply_quick_fix`) — мимо списка файлов задачи и мимо `Edit`;
- терминал и запуск (`execute_terminal_command`, `execute_run_configuration`, `build_project`, отладчик) — мимо разрешений `Bash`;
- БД (`execute_sql_query`, `create_database_connection` и др.) — только по `core/principles.md`, «Действия с БД», то есть не агентом.
