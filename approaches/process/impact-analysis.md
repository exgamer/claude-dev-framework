# Карта связей: что затронет изменение

Перед любым изменением существующего кода — рефактор, доработка, новая фича, которая встраивается в существующее, — нужно знать **всё, что зависит от изменяемого, и всё, от чего зависит оно само**. Иначе что-то забудем или сломаем там, где не смотрели.

Карту делает архитектор в Фазе 1 (раздел «Связи» в `design.md`), разработчик сверяется с ней при каждом изменении символа, ревью и QA проверяют по ней, что ничего не сломано.

---

## Что искать

### Входящие — кто зависит от изменяемого

| Связь | Как найти |
|---|---|
| Вызовы функций/методов/сервисов | поиск по имени символа (Go: `grep -rn 'Name(' internal`, gopls references, если доступен; PHP: по имени метода и по FQCN/интерфейсу) |
| Реализации интерфейса и его потребители | поиск по имени интерфейса; DI — `*_factory.go`, `app.go` / `definitions.php`, провайдеры |
| HTTP-клиенты эндпойнта | фронт, мобильные приложения (в т.ч. старые версии), другие сервисы, партнёры, железо — по URL и имени роута в доступных репозиториях; остальное — вопрос |
| Имя роута | генератор/сидер прав (fail-open, если имя перестанет попадать под конвенцию), `route()`-вызовы, ссылки во фронте |
| Потребители событий | кто слушает exchange/routing key; payload как контракт |
| Читатели/писатели данных | кто ещё читает и пишет таблицу/колонку (другие модули, сервисы, отчёты, BI, views, триггеры); кэш-ключи, которые читают другие |
| Консоль, крон, очереди | команды и расписания, обработчики очередей (`config/queue.php`, consumers_factory), feature-флаги |
| Тесты, Swagger, конфиг | тесты на изменяемое, аннотации, env-переменные |

### Исходящие — от чего зависит изменяемое

Репозитории и сервисы других модулей/доменов, внешние интеграции, события, которые потребляет, конфиг и секреты, кэш, транзакции.

### Неявные — то, что не находится по имени символа

- **Строковые значения**: статусы, типы, enum — `switch`/`match`/`map`, `Rule::in`/`in:`, swagger `enum:`, словари фронта, SQL-литералы, `const`-блоки.
- **Имена по строке**: DI по алиасу, рефлексия, имена очередей/exchange в конфиге, имена роутов, имена прав, ключи кэша, имена колонок в raw SQL.
- **Данные**: что лежит в колонках на stage/prod (новый NOT NULL, новое значение enum, смена типа).
- **Другие репозитории**: сервисы-потребители, которых нет в текущем проекте.

## Как собрать

1. Список изменяемого: символы (типы, функции, методы, интерфейсы), URL/роуты, события, таблицы/колонки, кэш-ключи, конфиг, значения enum.
2. По каждому пункту — поиск входящих, исходящих и неявных связей по таблице выше. Поиск — по имени **и** по строковому литералу.
3. Другие репозитории: доступны локально — поиск в них (только чтение); недоступны или неизвестно, кто потребляет, — **вопрос пользователю** в общий список («кто ещё вызывает `POST /…` / слушает `promocode.redeemed` / читает таблицу `…`?»).
4. Каждую найденную связь классифицировать:
   - **меняется вместе** — правка входит в план (своей задачей или в задачу изменения);
   - **сохраняется** — контракт не трогаем, нужен тест, что не сломано;
   - **проверено, не затронута** — с указанием, как проверено. Проверяется разово на ревью (`git diff` по путям), не постоянным автотестом: тест «легаси-потребитель по-прежнему вызывает легаси» упадёт в задаче, которая его переключает (ревью AINA-2744).

## Формат — раздел «Связи» в `design.md`

```markdown
## Связи

Изменяется: `TariffService.Update`, `PUT /admin/tariffs/{id}`, колонка `tariffs.grace_minutes`, enum `TariffStatus` (+`archived`).

| # | Связь | Тип | Где | Что делаем | Тест/проверка |
|---|---|---|---|---|---|
| C1 | `TariffService.Update` ← `UpdateTariffWorkflow` | вызов | internal/workflows/billing/tariff/… | меняется вместе (новая сигнатура) | unit workflow |
| C2 | `TariffStatus` → `switch` в `CalculateSessionDebt` | неявная (enum) | internal/workflows/… | меняется вместе: обработать `archived` | unit на `archived` |
| C3 | `PUT /admin/tariffs/{id}` ← админка (фронт) | HTTP | другой репозиторий | сохраняется: поля и ответ те же | регрессия API |
| C4 | `tariffs.grace_minutes` ← отчёт BI | данные | неизвестно | **вопрос пользователю** | — |

Не затронуто (проверено): события тарифа — не публикуются; кэш `tariff:*` — формат не меняется.
```

## Кто и как использует

| Роль | Что делает с картой |
|---|---|
| Архитектор | строит её в Фазе 1; связи «меняется вместе» — задачи в `plan.md`; неизвестные потребители — вопросы |
| Безопасник | проверяет связи с auth, правами, деньгами, внешними системами |
| Разработчик | перед изменением символа — ищет использования ещё раз (карта могла устареть); нашлась связь, которой нет в карте, — дописать её в «Связи» `design.md` и упомянуть в итоге; после изменений — повторный поиск по изменённым символам и литералам |
| Ревью | каждая связь «меняется вместе» — изменена, «сохраняется» — не сломана; изменённый символ, использование которого не учтено в карте, — **[ОШИБКА]** |
| QA | на связи «сохраняется» — регрессионные кейсы/тесты; на «меняется вместе» — кейсы на новое поведение |

Карта не нужна только для изменения, у которого нет внешних использований (новый файл, который ещё никто не вызывает) — и это тоже пишется одной строкой: «связей с существующим кодом нет, проверено поиском по …».
