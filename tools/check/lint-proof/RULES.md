# Правила, отданные анализаторам

Одна строка — одно правило фреймворка, которое проверяет анализатор (`core/rules-evolution.md`, «Статика первой»). Таблицу сверяет `python3 tools/check/lint-rules.py`: источник правила и тег существуют, правило есть в конфиге, у него есть случай в доказательстве, места запуска вызывают инструмент; и наоборот — каждое правило конфига и каждый случай доказательства есть в таблице. Текст правила остаётся в памятке и conventions — анализатор его не заменяет, а проверяет. На проекте эти правила гоняет `tools/lint/lint.py` конфигом фреймворка, без файлов в проекте (`tools/lint/README.md`).

Колонки: **Ловит точно** — что инструмент находит всегда (подтверждено случаями доказательства); **Остаток — агенту** — части того же правила, которые инструмент не видит: их проверяет агент. Ревьюер берёт остаток из конца вывода `lint.py` (печатается только у дошедшего до конца прогона, с находками или без) и проверяет по правилу только его; прогон не дошёл, не запускался или упал — всё правило. **Правило конфига** — для Go имя правила `depguard` или линтер/правило (`forbidigo`, `nlreturn`, `revive:<правило>`), для PHP — метод `LayersArchitecture` или `disallowed:<класс или функция>`; **Случаи** — имена из `CASES` скрипта доказательства через `;`; **Где запускается** — файлы, где вызывается прогон этого стека, через `;`: проверка фреймворка (Шаг 3а `/dev-rule`, стенд PHP) и роли — самопроверка разработчика и ревью (`tools/lint/lint.py` по диффу задачи).
