# Архивация тарифа — дизайн

1. **Что и зачем**: архивировать тариф вместо удаления, скрывать архивные в списке. Приёмка — AC1–AC4 (`requirements.md`).
2. **Связи**: список тарифов админки — меняется вместе (фильтр); назначение тарифа по умолчанию — меняется вместе (R4); кэш тарифа — сбросить после архивации; интеграционные эндпоинты — сохраняются (архивный там не меняет поведения в этой задаче); существующие признаки статуса тарифа, если есть, — связать с архивацией, а не дублировать (разработчик проверяет по коду).
3. **Домены и слои**: домен `internal/domains/billing/tariff` (переход «архивировать» — по правилам перехода состояния; соседний переход — `SetDefaultTariffCommand`), инфраструктура `internal/infrastructure/postgres/billing/tariff`, точка входа `internal/entrypoints/admin/http/billing/tariff`, миграция в `internal/migrations`; workflow не нужен (один домен).
4. **API**: `POST /…/admin/…/tariffs/{id}/archive` → успех как у соседних изменяющих эндпоинтов тарифа; 404 вне скоупа, 422 — R3/R4, невалидный id; список — параметр `archived` (0/1, по умолчанию 0).
5. **Данные / Схема БД**: `tariffs.archived_at TIMESTAMPTZ NULL` (как остальные отметки времени проекта), без значения по умолчанию, без заполнения старых строк; индекс под фильтр списка — по решению разработчика с обоснованием; `internal/migrations/<дата>_add_archived_at_to_tariffs_table.go`. **Границы транзакций**: одна запись — без транзакции. **Конкурентность**: архивация против назначения по умолчанию и повторная архивация — условный UPDATE (0 строк → 422).
6. **Требует согласования**: схема БД и изменение контракта списка — согласованы (`answers.md`).
7. **Выкатка**: сначала миграция (expand, обратно совместима), потом код; откат кода безопасен, откат миграции теряет отметки архива.
8. **Чувствительные зоны**: данные с владельцем (скоуп парковок) — существующий механизм скоупа, новых нет.
9. **SDK**: источник `git.mpinnovations.kz/mps/go-packages`, версии — из `go.mod` проекта (без изменений).
13. **Открытые вопросы**: нет.
