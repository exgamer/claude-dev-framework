# Эталонный модуль PHP: тарифы (Laravel + mps/core)

Один модуль целиком, написанный строго по правилам фреймворка. **Образец формы**: как оформить файл — смотреть сюда; бизнес-детали — в соседнем модуле проекта. Основан на модуле тарифов.

- Написан под `mps/core` **1.6.0** / `mps/utils` 2.6.2: менеджер транзакций — проектный `App\ParkingApp\Core\Database\Managers\TransactionManagerInterface` (+ `NoopTransactionManager`), потому что в ядре он появляется только с v1.10.0 (`mps-core/transactions.md`). В проекте с ядром ≥1.10 — интерфейс из ядра.
- Каркас подпроекта, на который опирается модуль, — в эталоне: корневой `ServiceProvider.php` и агрегатор `Infrastructure/ServiceProvider.php`, `Core/Requests/Request`, `Core/Providers/ServiceProvider`, `Core/Database/Managers/{TransactionManagerInterface,NoopTransactionManager}`, `Infrastructure/Postgres/Database/Managers/DatabaseTransactionManager` + биндинг в `Infrastructure/Postgres/Common/Providers/definitions.php` (`mock` → Noop), `Core/OpenApi` (`OA\Info`, схемы безопасности, `ValidationError422`, `ServerError500`), домен `Catalog/Parkings` — только `ParkingRepositoryInterface` (`oneById` ядра, `getMaxStayById`) и `ParkingMaxStayDto`.
- Считаются существующими (часть хоста): алиасы middleware в `bootstrap/app.php` (`auth:admin-api`, `permission:{право}`, `resolve.admin.parkings`, `verify.signature`, `api.response`); методы модели администратора `isSuperAdmin()`/`getParkingIds()`; ответы `NotFound404` и `AccessDenied403` в `Core/OpenApi`; биндинг реализации `ParkingRepositoryInterface`; exchange-и из `config/rabbit-config.php` — топология хоста. `config/*.php`, `routes/console.php`, `.env.example` — фрагменты приложения.
- Пагинация (P-19, P-22): модуль написан формой (2) — `Core/Database/Query/Page` + `Core/Resources/PaginatedResource` (в ядре 1.6.0 и 1.10.2 их нет, место — `structure.md`). Классы формы (1) — `Core/Resources/PaginateResource`, `Core/Database/Query/PaginatedQueryHelper`, `Core/Requests/SearchRequest` — лежат рядом как образец подпроекта, модуль их не использует.
- Healthcheck — готовый `MPS\Utils\Components\HealthCheck` из `mps/utils` (`/health/liveness`, `/health/readiness`: БД, кеш, RabbitMQ), своего нет (`mps-core/capabilities.md`).
- Сценарий внешних систем общий с Go-эталоном: лимит цены из реестра `CityParking` проверяется до транзакции; после коммита тариф уходит в `PartnerBilling`, ошибка отправки — в Sentry через `ExceptionHandler::report()`, запрос не падает. Лимит проверяется только при создании (`update` его не проверяет — граница сценария эталона).
- **Проверено 2026-10-20:** `php -l` в docker `php:8.3-cli` по всем 138 файлам; phpunit/phpstan не запускались (нет vendor). API ядра сверено со справочником `mps-core/reference/mps-core-v1.6.0.md`, `mps-utils-v2.6.2.md` и `mps-core/official/utils-v2.8.4/http-client.md`; Laravel-API (`paginate(perPage:, page:)`, `FormRequest::validated($key, $default)`, `PendingRequest::timeout()`, `ConnectionException`, `QueryException::getCode()`) — по документации Laravel, без сверки с версией проекта.
- При изменении правила или версии ядра — поправить пример.
