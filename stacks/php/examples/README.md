# Эталонный модуль PHP: тарифы (Laravel + mps/core)

Один модуль целиком, написанный строго по правилам фреймворка. **Образец формы**: как оформить файл — смотреть сюда; бизнес-детали — в соседнем модуле проекта. Основан на модуле тарифов.

- Написан под `mps/core` **1.6.0** / `mps/utils` 2.6.2: менеджер транзакций — проектный `App\ParkingApp\Core\Database\Managers\TransactionManagerInterface` (+ `NoopTransactionManager`), потому что в ядре он появляется только с v1.10.0 (`mps-core/transactions.md`). В проекте с ядром ≥1.10 — интерфейс из ядра.
- Каркас подпроекта, на который опирается модуль, — в эталоне: корневой `ServiceProvider.php` и агрегатор `Infrastructure/ServiceProvider.php`, `Core/Requests/Request`, `Core/Providers/ServiceProvider`, `Core/Database/Managers/{TransactionManagerInterface,NoopTransactionManager}`, `Infrastructure/Postgres/Database/Managers/DatabaseTransactionManager` + биндинг в `Infrastructure/Postgres/Common/Providers/definitions.php` (`mock` → Noop), `Core/OpenApi` (`OA\Info`, схемы безопасности, общие ответы `Unauthorized401`/`AccessDenied403`/`NotFound404`/`ValidationError422`/`ServerError500`/`ServiceUnavailable503`, схема `CurrencyEnum` enum ядра), `Core/Exceptions/ServerConfigurationException`, домен `Catalog/Parkings` — только `ParkingRepositoryInterface` (`oneById` ядра, `getMaxStayById`) и `ParkingMaxStayDto`.
- Считаются существующими (часть хоста): алиасы middleware в `bootstrap/app.php` (`auth:admin-api`, `permission:{право}`, `resolve.admin.parkings`, `verify.signature`, `api.response`); методы модели администратора `isSuperAdmin()`/`getParkingIds()`; биндинг реализации `ParkingRepositoryInterface`; exchange-и из `config/rabbit-config.php` — топология хоста. `config/*.php`, `routes/console.php`, `.env.example` — фрагменты приложения; таймаут запроса к БД — `statement_timeout` 10 с в `config/database.php` (`server_options` подключения `pgsql`, `DB_STATEMENT_TIMEOUT_MS`, `approaches/patterns/performance.md`).
- Пагинация (P-19, P-22): модуль написан формой (2) — `Core/Database/Query/Page` + `Core/Resources/PaginatedResource` (в ядре 1.6.0 и 1.10.2 их нет, место — `structure.md`). Классы формы (1) — `Core/Resources/PaginateResource`, `Core/Database/Query/PaginatedQueryHelper`, `Core/Requests/SearchRequest` — лежат рядом как образец подпроекта, модуль их не использует.
- Healthcheck — готовый `MPS\Utils\Components\HealthCheck` из `mps/utils` (`/health/liveness`, `/health/readiness`: БД, кеш, RabbitMQ), своего нет (`mps-core/capabilities.md`).
- Сценарий внешних систем общий с Go-эталоном: лимит цены из реестра `CityParking` проверяется до транзакции; после коммита тариф уходит в `PartnerBilling`, ошибка отправки — в Sentry через `ExceptionHandler::report()`, запрос не падает.
- **Граница примера** (бизнес-правила эталона; в задаче — по ТЗ, не правило фреймворка):
  - проверки при правке: `PUT` (`TariffCrudService::update`) не повторяет междоменных проверок создания — лимит цены реестра, льготный период против наибольшей стоянки парковки, состояние парковки при переносе `parking_id`; отклонённый при создании тариф получается правкой. Нужны — `UpdateTariffWorkflow` с теми же проверками;
  - тариф по умолчанию: флаг может остаться у архивного — массовый архив (`archiveNotArchivedByParkingId`) его не снимает; назначить по умолчанию можно только действующий (`set-default` архивного или запланированного, даже с флагом, — 422);
  - уведомление партнёра — без гарантии доставки: отправка после коммита, сбой — `report()`, повтора нет (событие брокеру — через outbox). Нужна гарантия — outbox и для партнёра;
  - `FAILED` outbox — «ручной разбор» как потребитель статуса (`approaches/patterns/outbox.md`): алерт — `OperationFailedAppException` «нужен ручной разбор» уходит в `report()` (трекер) из первой отправки и из повтора, выборка — статус последнего события в `GET tariffs/default` и `status = 'failed'` в `parking.outbox_tariff_events`.
- **Анализаторы:** `phpstan-rules.neon` + `tests/Architecture/LayersArchitecture.php` — механические правила памятки, которые проверяет phpstan проекта: границы слоёв и доменов (phpat: домен без `Infrastructure` — кроме Eloquent-модели, P-4, — `Entrypoints`, `Workflows`; Billing и Catalog не знают друг друга; модуль домена не знает соседний модуль, `Domains/Billing/Common/` — ни одного модуля домена; `Common/` без зависимостей от слоёв; workflow не вызывает workflow; точка входа без `Infrastructure`), фасад `DB` только в реализации менеджера транзакций и миграциях, `app()`/`resolve()` вне провайдеров (`*ServiceProvider.php`, `Providers/`) и `definitions.php` (`phpstan-disallowed-calls`). В проекте эти правила гоняет `tools/lint/lint.py php` фреймворка своим конфигом и своими инструментами — в проект ничего не кладётся, его `phpstan.neon` не трогается (`tools/lint/README.md`); правила доменов собираются по `Domains/*` подпроекта.
- **Проверено 2026-10-27:** `tools/php-check/run.sh` в docker-контейнере с PHP 8.5 (Laravel 12, `mps/core` 1.6.0, `mps/utils` 2.6.2, testbench): phpunit — 166 тестов OK, phpstan (larastan) уровень 5 — 0 ошибок; хост в стенде — `tools/php-check/tests/TestCase.php` (провайдеры, алиасы middleware, `config/*.php`) и заглушка `App\Http\Controllers\Controller`. Миграции на живой БД не прогонялись. API ядра сверено со справочником `mps-core/reference/mps-core-v1.6.0.md`, `mps-utils-v2.6.2.md` и `mps-core/official/utils-v2.8.4/http-client.md`; Laravel-API (`paginate(perPage:, page:)`, `FormRequest::validated($key, $default)`, `PendingRequest::timeout()`, `ConnectionException`, `QueryException::getCode()`) — по документации Laravel, без сверки с версией проекта.
- При изменении правила или версии ядра — поправить пример.

## Событие `tariff.created`

Контракт сообщения (`regulations/contracts.md`, «Что фиксирует контракт»): назначение — новый тариф создан (подписчики — системы, которым нужен список тарифов парковки); exchange — из `app.rabbit-config.billing.tariff-events.exchange` (`config/rabbit-config.php`, topic), persistent-сообщения, routing key `tariff.created` (`OutboxTariffEventRoutingKeyEnum`), тело JSON (`Infrastructure/RabbitMQ/Billing/OutboxTariffEvents/Publishers/OutboxTariffEventPublisher.php`), заголовок `event_id`. Поля обязательны; `null` — только у `grace_minutes`.

| Поле | Тип | Смысл |
|---|---|---|
| `event_id` | int | ID записи outbox; одинаков при повторной отправке — ключ дедупликации |
| `tariff_id` | int | ID тарифа |
| `parking_id` | int | ID парковки |
| `name` | string | название тарифа на момент события |
| `currency` | string | ISO 4217 (`CurrencyEnum` ядра) |
| `price` | int | цена часа в минимальных единицах валюты |
| `grace_minutes` | int\|null | доп. время на выезд после оплаты, минуты; `null` — без льготного периода |

Доставка — at-least-once: событие пишется в транзакции тарифа (`CreateTariffWorkflow`), отправляется после коммита и повторяется `billing:outbox-tariff-events:retry` до `published` или `failed`. Подтверждения брокера ядро не ждёт: `published` — сообщение передано в канал; сбой после передачи и до `markPublished` — событие уйдёт ещё раз. Получатель обязан отсекать повтор по `event_id` (хранить обработанные). Порядок событий между тарифами не гарантирован. Новое поле — добавляется, существующее не меняет тип и смысл; несовместимое изменение — новый routing key. Расхождение с Go (`grace_minutes` без `null`, подтверждение брокера) — особенность примера, у одного события в задаче один контракт.
