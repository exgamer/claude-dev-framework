# Эталонный модуль Go: тариф

Один модуль целиком, написанный строго по правилам фреймворка. Это **образец формы**: при сомнении, как оформить файл, смотреть сюда, а детали (имена полей, бизнес-правила) брать из соседнего модуля проекта. Основан на модуле тарифов.

- Модуль Go — заглушка `example.com/parking-service`. Пути SDK — `git.mpinnovations.kz/mps/go-packages/gosdk-*`; источник и версия SDK на задаче — из `go.mod` проекта, у нового проекта — вопрос (`conventions.md`, п. 23).
- Проверено 2026-10-20: свой `go.mod`/`go.sum`, сборка офлайн из module cache против gosdk-core v1.0.9, gosdk-db-core v1.0.10, gosdk-http-core v1.0.14, gosdk-http-request-builder v1.0.2, gosdk-postgres-core v1.0.8, gosdk-redis-core v1.0.7, gosdk-rabbit-core v1.0.10, gosdk-sentry-core v1.0.5, gosdk-console-core v1.0.6 (Go 1.26+). Из каталога эталона:
  ```sh
  export GOFLAGS=-mod=mod GOPROXY=off GOSUMDB=off GOPRIVATE= GONOPROXY=
  go build ./... && go vet ./... && go test -race ./... && gofmt -l .
  ```
- Эталон — полный сервис: `main.go` + `internal/app/app.go` (HTTP, consumer, первая отправка outbox) и `cmd/console` (миграции, повтор outbox по cron). Домены `handbook/parking`, `identity/admin`, `identity/partner` и их реализации (Postgres, Redis, JWT), регистрация `*admin.Service`/`*partner.Service` в DI — в эталоне; «считающихся существующими» частей нет, кроме схемы БД: таблицы `parking.tariffs`, `parking.parkings` и общей БД администраторов уже есть в базе — миграции эталона их только меняют (`ALTER`, индекс, FK) и создают outbox. Каталог `docs/` (swag) не хранится — генерируется командой из строки `main.go`.
- При изменении правила или SDK — поправить пример и перепроверить сборку.
