# Требования к сервису

Выжимка из `BACKEND-SERVICE-REQUIREMENTS.md`. Проверяется при создании нового сервиса и на ревью инфраструктурных изменений.

---

- **Конфиг** — только из env. Актуальный `.env.example` со всеми параметрами. Хардкод конфигурации и секреты в репозитории запрещены. Обязательная настройка отсутствует или пуста — приложение не стартует (Go — ошибка/`panic` при инициализации, единственное место, где он допустим; PHP — свой наследник `InvalidConfigurationAppException` с 500 в провайдере/конструкторе адаптера, `stacks/php/mps-core/exceptions.md`), не молчаливый дефолт `?? ''` (`adapter-missing-config-validation`). Динамические ключи (`PARKING_HOST_<id>`) валидируются на старте так же. Хосты и URL нормализуются при чтении конфига (хвостовой `/`, схема), не в каждом вызове.
- **Логи** — stdout, структурированные: уровень, время, id сервиса, информация о запросе, сообщение, контекст.
- **Ошибки** — централизованный трекинг (Sentry). Сбой консольной команды и крона — тоже в трекер, не только в вывод команды (тег `console-failure-not-reported`): вывод крона никто не читает. Go — `errorreporter`, PHP — `ExceptionHandler::report()` (`stacks/php/conventions.md` п. 17a).
- **Метрики** — количество запросов, latency, ошибки, распределение статусов; без персональных данных, секретов и значений с неконтролируемой кардинальностью.
- **Healthcheck** — liveness (сервис жив) и readiness (доступны БД, брокеры, обязательные ресурсы).
- **API-документация** — автогенерация (Swagger).
- **Code style и статанализ** — есть инструменты и команды для их запуска.
- **README** — назначение, зона ответственности, ссылка на API-доку, контакты, локальный запуск, деплой.
- **Контейнер** — готов к запуску в контейнере.
- **Тесты** — критические бизнес-флоу покрыты.
