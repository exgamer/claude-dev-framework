# Git: ветки, коммиты, MR

Выжимка из `BRANCH-NAMING-CONVENTION.md`, `COMMIT-NAMING-CONVENTION.md`, `GITFLOW.md`. Ревью — приём MR, префиксы замечаний, разногласия — `code-review.md`.

> Модель никогда не делает `commit`/`push` без явного подтверждения на каждый раз.

---

## Ветки

- Имя ветки = ключ задачи, строго `PROJECTKEY-номер`: `AINA-722`.
- Запрещено: `feature/AINA-722`, `AINA-722-fix`, `AINA_722`, `aina-722`, `AINA722`.
- Рабочая ветка создаётся от `release`; hotfix — от `production`.
- Поток: ветка задачи → MR → `stage` (тест) → `release` → `production`. Править прямо в `stage` нельзя.
- Репозиторий без `release` (пакет библиотеки — раздел «Задача в пакете библиотеки») — ветка задачи от основной ветки (`main`), база ревью — она же, у пакета — тег после слияния. Каждый коммит, пуш и тег — по своему «да».

## Задача в пакете библиотеки

Проект задачи — сам пакет, который подключают другие: Go SDK (`gosdk-*`, `go-sdk-*-core`), ядро и утилиты PHP (`mps/core`, `mps/utils`), общая библиотека. Правила стека — по коду пакета, плюс выпуск. Почему: у пакета потребители, которые получают изменение при обновлении версии, не читая код.

- **Версия** — semver от последнего тега в `origin` (`git ls-remote --tags origin`, не локальный `git describe`): исправление без смены поведения — патч; новая настройка или смена поведения по умолчанию — минор; несовместимая смена публичного API — вопрос пользователю (мажор или новая функция рядом со старой, O-29).
- **Новое поведение, которое открывает доступ или данные** (маршрут документации, отладка, подробные ошибки) — по умолчанию выключено, включается явной настройкой; пустое или нераспознанное значение — выключено и `WARN` в лог с допустимыми значениями; состояние настройки — строкой в лог при старте (`api-docs-exposed`, `approaches/process/security.md`).
- **CHANGELOG** — запись в формате своего файла (заголовки версий как в файле); смена поведения — отдельной пометкой с тем, что делать потребителю; файла нет — не создавать без вопроса. Новая env-переменная — ещё в `README` пакета и в шаблоне сервиса: `.env.example` и документация, где настройка описана (`approaches/process/impact-analysis.md`, «Тесты, Swagger, конфиг»).
- **Ветка и тег** — у пакета нет `release`: ветка задачи — от основной ветки (`main`), база ревью — `main`, тег — после слияния, на коммите основной ветки; каждый коммит, пуш и тег — по своему «да» (`core/principles.md`, «Git»).
- **Потребители** подключают новую версию отдельным шагом после тега — обновлением версии в менеджере зависимостей, не локальной подменой пути (особенности стека — Go: `stacks/go/conventions.md` п. 24).

## Коммиты

```
тип: описание #КЛЮЧ-задачи
```

| Тип | Когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага без новой функциональности |
| `refactor` | рефакторинг без изменения поведения |
| `perf` | оптимизация производительности |
| `conf` | конфиги, CI, env, yaml |

- Описание по-русски, с маленькой буквы, без точки, до 70 символов; что сделано, без «комплексно»/«в рамках» — `core/style.md`, «Любой текст для людей».
- Одна логическая задача — один коммит (squash перед merge при необходимости).
- Без трейлеров и подписей ИИ: никаких `Co-Authored-By: Claude …`, `Claude-Session: …`, «🤖 Generated with Claude Code» — ни в коммите, ни в описании MR (`core/principles.md`, «Git»).

```
feat: добавлен расчёт долга по тарифу #AINA-722
fix: исправлено кэширование ошибок шлюза kassa24 #AINA-801
```

## MR

Условия приёма на ревью, префиксы замечаний (`blocking:`, `suggestion:`/`nit:`, `question:`, `praise:`), обязанности автора и ревьюера, эскалация — `code-review.md`.
