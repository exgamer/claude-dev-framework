# /dev-qa

`{DF}` — `.claude/dev-framework` в проекте, иначе `~/.claude/dev-framework`.

## Шаг 1 — Источник

`docs/tasks/<ключ>/design.md` (критерии приёмки, API, правила), `threats.md` (колонка «Тест» — негативные кейсы безопасности обязательны) или описание задачи от пользователя. Нет критериев — спроси, не выдумывай.

## Шаг 2 — Тест-кейсы

`docs/tasks/<ключ>/qa.md`: на каждый критерий — позитивный сценарий, негативные (валидация, нет доступа, нет записи, чужой контекст), граничные (пустые списки, лимиты, повторный запрос/идемпотентность, параллельный запрос). Формат: id, предусловия, шаги, ожидаемый результат, приоритет.

## Шаг 3 — Автотесты

- Go: раскладка — `{DF}/stacks/go/structure.md`, раздел «Тесты» (unit рядом, интеграционные с тегом `integration`, e2e в `tests/`); fakes по интерфейсам, `testify` assert/require.
- PHP: раскладка — `{DF}/stacks/php/structure.md`, раздел «Тесты» (`tests/Unit|Feature/{Подпроект}/…`); как писать — `{DF}/stacks/php/mps-core/tests.md`.
- UI: Python + Playwright + pytest (POM) по `{DF}/stacks/qa-playwright/conventions.md`.
- Живая инфраструктура — только уже поднятые общие контейнеры (`docker ps`), тестовые данные удаляются после прогона.

## Шаг 4 — Итог

Что покрыто автотестами, что только кейсами, результат прогона (или «не запускал»). Найденные баги — отдельным списком с шагами воспроизведения.
