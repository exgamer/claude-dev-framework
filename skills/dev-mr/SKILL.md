# /dev-mr

Сторона автора MR: ревьюеры оставили замечания — разобрать каждое вместе с пользователем, исправить принятое, обосновать отклонённое, спорное довести до правил. Ревью кода нами — `/dev-review` (в т.ч. `--mr`).

`{DF}` — `.claude/dev-framework` в проекте, если есть, иначе `~/.claude/dev-framework`.

```
/dev-mr <id-or-url>            # открытые треды ревьюеров
/dev-mr <id-or-url> --all      # и закрытые тоже
/dev-mr <id-or-url> --no-post  # ответы в треды не публиковать
```

## Шаг 1 — Контекст

Прочитай `{DF}/approaches/process/mr-threads.md` — процедура целиком: MR и ветка, выгрузка тредов, префиксы, анализ, документ, две остановки на обсуждение, выполнение, итог. Выполняй по шагам. Также: `{DF}/regulations/code-review.md` (префиксы, обязанности автора, соответствие уровням фреймворка), `{DF}/core/principles.md` («Пробелы и споры», «Действия с БД»), `{DF}/core/decisions.md`, `{DF}/core/rules-evolution.md` («Лог отклонений по задаче»). Локальные `.claude/dev-rules.md` проекта главнее фреймворка.

Метка продолжения — `python3 {DF}/tools/resume/resume.py set dev-mr <iid>` (флаги — `--flags "--all --no-post"`; каждый вызов `resume.py` — с `--project <корень проекта>`): после `/clear` или в новой сессии пользователю хватит «дальше». Продолжение: `docs/tasks/<ключ>/mr-<iid>.md` уже есть — продолжай с него, не выгружай и не переписывай заново: решения пользователя и статусы в нём; ответ, уже опубликованный в тред, повторно не публикуй (сверь с тредом в `glab`).

Проверь доступ к IDE и при недоступности предложи включить — `{DF}/approaches/process/code-navigation.md`, «Проверка при старте»; работу это не останавливает. Поиск по коду при анализе и правках — по тому же файлу.

## Шаг 2 — Правила стека

Для сверки замечаний с правилами: `{DF}/stacks/<stack>/checklist.md` всегда; каталоги тегов (`{DF}/approaches/process/review-tags.md`, `{DF}/stacks/<stack>/review-tags.md`) и каталог тегов безопасности (`{DF}/approaches/process/security.md`, «Каталог тегов безопасности»); `security.md`, `review-findings.md` стека; остальное (`conventions.md`, `style.md`, `mps-core/*` / `go-sdk/*`, `{DF}/approaches/patterns/*`) — grep по теме замечания, не целиком. Для правок — как разработчик стека: `{DF}/skills/dev-<stack>/SKILL.md`, Шаги «Правила», «Что уже есть в SDK» / «Что уже есть в ядре», «Образец», «Код».

## Остановки

1. Документ `docs/tasks/<ключ>/mr-<iid>.md` с таблицей замечаний → обсуждение с пользователем: вопросы и варианты текстом одним списком, с рекомендацией по каждой строке; дальше — только по его решениям.
2. План правок вместе с текстами ответов в треды (по «Как писать ответ» из `mr-threads.md`: по делу, 1–3 предложения, без благодарностей и канцелярита, без упоминания фреймворка) → обсуждение → «да». Это «да» разрешает публикацию ответов: отказы и ответы на вопросы — сразу, «исправлено» с хэшем — после пуша. Текст поменялся — показать и получить «да» заново.
3. Коммит и пуш — каждый по отдельному «да»; в коммите и ответах в треды — без подписей и трейлеров Claude (`{DF}/core/principles.md`, «Git»). Треды не резолвить, правила фреймворка не править (строки в `rules-log.md`, разбор — `/dev-rule`).

## Итог

Не длиннее 15 строк: исправлено / отклонено / отвечено / в `/dev`; опубликовано ответов и что осталось черновиком; тесты и линтер; строк в `rules-log.md` и предложение `/dev-rule <путь>`; что ждёт подтверждения. После итога — снять метку продолжения: `python3 {DF}/tools/resume/resume.py done dev-mr <iid>`.
